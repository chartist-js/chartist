Chartist keeps its core small and leaves the extras to you. Tooltips, value labels, legends, a bar that turns red past a threshold: none of them are options. Instead, every step of drawing a chart is an event, and a listener can change what that step produces. A plugin is a set of such listeners with a name, ready to share.

## The pipeline

A chart goes through seven phases, in this order. The first five build the chart's scene, a plain tree of SVG nodes, without touching the page; the last two put it there:

<Diagram
  source={pipeline}
  caption='A render runs the phases top to bottom, each with an event. A resize starts again at layout, and toScene() stops after scene.'
/>

Each phase emits an event with what it produced:

| Phase     | Payload                                                             | What it is                                                                               |
| --------- | ------------------------------------------------------------------- | ---------------------------------------------------------------------------------------- |
| `resolve` | `{ config }`                                                        | The config with defaults applied: padding, coordinates, layers, axes                     |
| `prepare` | `{ data }`                                                          | The data, each series as `{ values, name, className, meta }`                             |
| `layout`  | `{ width, height, padding, area }`                                  | The chart's size and the drawing area inside the padding and axes                        |
| `compose` | a scene node                                                        | Each element the layers draw: series, lines, points, bars, slices, grid lines and labels |
| `scene`   | `{ scene }`                                                         | The whole tree, its root the `svg`                                                       |
| `render`  | `{ scene, output, cause, previous, changes }`                       | The renderer has written the SVG, or changed it in place                                 |
| `mount`   | `{ scene, output, cause, previous, changes, elementOf, animation }` | The SVG is in the page; `elementOf(node)` gives you a node's element                     |

A listener that returns a new payload changes the phase, and later phases build on the change. Return nothing to leave it as it is. By `render` and `mount`, the SVG exists: `render` listeners only watch, and a `mount` listener may return a function that undoes what it did (see [Cleaning up](#cleaning-up)). Other return values of theirs are ignored.

`render` and `mount` also say why the chart rendered and what the render did: `cause` is `create`, `hydrate` (a chart that [took server markup over](../ssr-hydration/)), `update`, `resize`, `responsive` or `fonts`, `previous` is the previous render's scene, and `changes` lists every node that was added, updated or removed. `mount` also has the `animation` timing when the chart [animates its update](../live-updates/#animate-updates). [Live updates](../live-updates/#what-changed) has the details.

When the container resizes, the chart runs again from `layout`. The config and data haven't changed, so `resolve` and `prepare` don't run, and their listeners aren't called.

## Listening

Pass listeners in the config of `chart()`, by phase name:

```ts
import { autoScaleAxis, cartesianAxes, chart, line, stepAxis } from 'chartist';

chart('#chart', {
  data: { labels: ['Mon', 'Tue', 'Wed'], series: [[1, 3, 2]] },
  axes: cartesianAxes([
    { id: 'x', side: 'bottom', type: stepAxis() },
    { id: 'y', side: 'left', type: autoScaleAxis() }
  ]),
  layers: [line()],
  on: {
    layout: ({ width, height }) =>
      console.log(`laid out at ${width}×${height}`),
    mount: ({ scene }) => console.log('mounted', scene)
  }
});
```

The presets take the same listeners:

```ts
import { lineChart } from 'chartist';

lineChart(
  '#chart',
  { series: [[1, 3, 2]] },
  { on: { mount: () => console.log('drawn') } }
);
```

Or call `on()` and `off()` on the chart handle. Both return the handle, so they chain. `off(name, listener)` removes that listener. `off(name)` without one removes the listeners you added to that event, with `on()` or in the `on` config, and leaves the ones of plugins alone. The name `'*'` listens to all events, with the event name as the first argument:

```ts
import { lineChart } from 'chartist';

const chart = lineChart('#chart', { series: [[1, 3, 2]] });

const log = (name: string, payload: unknown) => console.log(name, payload);
chart.on('*', log);
chart.update({}); // logs every phase of this render
chart.off('*', log);
```

<Callout>
  **The first render happens right away.** `chart()` and the presets draw the
  chart before they return, so a listener added with `on()` afterwards sees the
  next render, not the first. For the first one, pass it in `on`, or use a
  plugin.
</Callout>

## Scene nodes

The `compose` event is where most plugins work. Its payload is a scene node: a plain description of an SVG element with its `name`, `attrs`, `classes` and `children`, plus what Chartist knows about it:

- `role`: `series`, `line`, `point`, `area`, `bar`, `slice`, `grid`, `gridBackground` or `label`
- `ctx`: its data, such as `seriesIndex`, `valueIndex`, `value` and `meta`
- `key`: a stable id like `0/1/3` (layer, series, value)

In TypeScript, checking the role narrows the node: after `node.role === 'point'`, `node.ctx.x` is a number and `node.ctx.path` is an error, since only lines, areas and slices have a path. `findAll(scene, { role: 'bar' })` returns bar nodes, and the builder methods keep the type. The live examples' editor shows it too: type `node.ctx.` inside a role check, and it lists that role's fields. If your plugin adds nodes with a role of its own, declare it in the `NodeRoles` interface, the same way as [custom events](#custom-events).

Every node with a role passes through the listeners, children before their parents. So a series listener sees its points and lines as the other listeners left them.

Nodes are immutable. Their methods (`attr()`, `addClass()`, `removeClass()`, `append()`, `remove()`, `replace()`, `text()`, `empty()`) return a new node, and you return that node from the listener.

### Change, replace or drop

To change a node, return it with new attributes or classes, as above. To replace it, return a different node; keep its `role`, `ctx` and `key` so later listeners still know what it is. To drop it, return `null`:

```ts
import { node, type ChartPlugin } from 'chartist';

/** Circles instead of points, and no points for zero values. */
export const circles: ChartPlugin = {
  name: 'circles',
  install(chart) {
    chart.on('compose', current => {
      if (current.role !== 'point') {
        return;
      }
      const { x, y, value } = current.ctx;
      // Line values are { x, y } (or a hole).
      if (value && typeof value === 'object' && 'y' in value && value.y === 0) {
        return null;
      }
      return node('circle', { cx: x, cy: y, r: 5 }, 'ct-circle', {
        role: current.role,
        ctx: current.ctx,
        key: current.key
      });
    });
  }
};
```

The circle has none of the point's classes, so style it yourself, for example with `.ct-circle { fill: var(--ct-color); }`.

### Decorate

To add elements, append them to a parent. A value above each bar goes into the bar's series, which comes through the listener after its bars:

```ts
import { node, type ChartPlugin } from 'chartist';

export const valueLabels: ChartPlugin = {
  name: 'value-labels',
  install(chart) {
    chart.on('compose', series => {
      if (series.role !== 'series') {
        return;
      }
      return series.children
        .filter(child => child.role === 'bar')
        .reduce((result, bar) => {
          const { x2, y2 } = bar.attrs;
          const { value: v } = bar.ctx;
          const value =
            v && typeof v === 'object' && 'y' in v ? v.y : undefined;
          return result.append(
            node(
              'text',
              { x: x2, y: y2 - 8, 'text-anchor': 'middle' },
              'ct-value'
            ).text(String(value))
          );
        }, series);
    });
  }
};
```

## Writing a plugin

A plugin is an object with a `name` and an `install` function. `install` runs once, before the first render, with the chart handle, and registers listeners on it. They stay for every later render, after updates and resizes too. For options, write a function that returns the plugin:

```ts
import { barChart, type ChartPlugin } from 'chartist';

/** Bars at or above the limit get the class ct-over. */
const threshold = (limit: number): ChartPlugin => ({
  name: 'threshold',
  install(chart) {
    chart.on('compose', current => {
      if (current.role !== 'bar') {
        return;
      }
      // A number, { x, y } (with an X scale axis) or a hole.
      const { value } = current.ctx;
      const y =
        typeof value === 'number'
          ? value
          : value && 'y' in value
            ? value.y
            : undefined;
      return y !== undefined && y >= limit
        ? current.addClass('ct-over')
        : undefined;
    });
  }
});

barChart(
  '#chart',
  { labels: ['Q1', 'Q2', 'Q3', 'Q4'], series: [[5, 4, 3, 7]] },
  { plugins: [threshold(5)] }
);
```

Plugins go into `plugins`, in the config of `chart()` or the options of the presets. Plugins install in order, so with two listeners on the same event, the earlier plugin's runs first. `chart()` also takes a `[plugin, options]` pair as an entry, and `install` receives the options as its second argument.

## Cleaning up

What a plugin sets up outside the chart has to go when the chart goes. `install` may return a function, and `destroy()` calls it once, after the chart's SVG is removed. `detach()` doesn't: a detached chart keeps its SVG and its plugins.

```ts
import type { ChartPlugin } from 'chartist';

/** Logs the chart's size while the Shift key is down. */
export const shiftToMeasure: ChartPlugin = {
  name: 'shift-to-measure',
  install(chart) {
    const onKey = (event: KeyboardEvent) => {
      if (event.key === 'Shift') {
        const box = chart.container?.getBoundingClientRect();
        console.log(`${box?.width} x ${box?.height}`);
      }
    };
    document.addEventListener('keydown', onKey);
    return () => document.removeEventListener('keydown', onKey);
  }
};
```

A `mount` listener may return a function too, for what it did to the elements of one render. It runs before the next render touches the SVG, and on `destroy()`. Use it when the next render needs a clean slate, such as a `title` with a point's value. For what you set up once per element, like event listeners, act on the `add` changes instead. [Live updates](../live-updates/#cleaning-up) shows both.

## Custom events

Plugins can emit events of their own with `chart.emit(name, payload)`. Declare each event and its payload in the `ChartEvents` interface (TypeScript merges your declaration into Chartist's), list it in `provides`, and listen to it with `on()` like to any other event. A misspelled name or a wrong payload is then a type error, not a silent no-op. This plugin reports clicks on bars; the page listens and shows the clicked value. Press **Edit** and click a bar:

The click handlers go on in `mount`, the first phase in which the elements exist, and only on elements that are new in the page: those of `add` changes. With the default renderer, every render draws a new SVG, so every element is new, and the old ones go away with their handlers. With [`liveDomRenderer()`](../live-updates/#keep-the-svg), a bar can stay the same element for many renders, and a handler added on every render would fire once for each of them. What a kept bar stands for can change, so the plugin notes it per element from `add` and `update` changes, and the handler reads it when it fires.

Phase names are reserved: emitting `compose` or `mount` throws. A prefix such as `bar:` keeps your names apart from other plugins'.

## Plugins for live updates

A chart drawn with [`liveDomRenderer()`](../live-updates/) keeps its elements from one render to the next. That's good news for plugins: what they add to an element stays, hover and focus survive an update, and their own elements can move with the chart instead of popping in again. It asks a little more of them, though.

This tooltip plugin shows the value of the point under the pointer. The chart gets a new value every second, and the tooltip stays on its point, shows the point's new value and moves in step with the chart's update animation. Press **Edit** and hover a point:

### New elements, kept elements

`mount` comes after every render, and in a live chart most of its elements were there before. Add listeners on `add` changes only, as the tooltip does, or they pile up on kept elements. Read what an element shows when you need it (the tooltip reads `ct:value` when it shows), not when you add the listener: a kept point can get a new value. And return a cleanup function from `install` for what lives outside the SVG, like the tooltip's element.

### Keys for your own nodes

Nodes a plugin adds are matched between renders too, so they keep their elements. Without a key, a node is matched by its element name, its first class and its place among siblings like it. Give it a key with `node()` when that's not enough, for nodes that come and go or change their order:

```ts
import { node, type ChartPlugin } from 'chartist';

/** Writes the last value of each line next to its end. */
export const lastValue: ChartPlugin = {
  name: 'last-value',
  install(chart) {
    chart.on('compose', series => {
      if (series.role !== 'series') {
        return;
      }
      const points = series.children.filter(child => child.role === 'point');
      const last = points.at(-1);
      if (!last) {
        return;
      }
      const { x1, y1 } = last.attrs;
      return series.append(
        node('text', { x: Number(x1) + 8, y: y1 }, 'ct-last-value', {
          key: `last-value/${series.ctx.seriesIndex}`
        }).text(String(last.attrs['ct:value']))
      );
    });
  }
};
```

### Keyframes

With update animations, numbers move from their old to their new value, and paths with the same commands move point by point. That's right for most nodes. For a node that should move differently, such as a needle that turns around its center, give the plugin `keyframes()`. The renderer asks it once per update, with the progress points of the chart's easing: 0 is the old node, 1 the new one, and points beyond them come from an easing that overshoots. The plugin returns one set of attributes per point, or nothing for the default:

```ts
import type { ChartPlugin } from 'chartist';

/**
 * Turns the needle a gauge plugin draws, instead of morphing its path.
 * The gauge gives the needle's path its angle in `ct:angle`.
 */
export const turningNeedle: ChartPlugin = {
  name: 'turning-needle',
  install() {},
  keyframes(previous, next, progress) {
    if (!next.classes.includes('ct-needle')) {
      return undefined;
    }
    const from = Number(previous.attrs['ct:angle']);
    const to = Number(next.attrs['ct:angle']);
    return progress.map(p => ({
      transform: `rotate(${from + (to - from) * p} 100 100)`
    }));
  }
};
```

Plugins are asked first, in their order, then the layer that drew the node, so a plugin can also change how a built-in node moves. [Custom layers](../custom-layers/) can have `keyframes()` too.

### Animate in step

When the chart animates an update, `mount` gets its `animation`: the duration in milliseconds and the easing as a CSS string. Animate what your plugin draws with it, and it moves with the chart. For HTML elements, pass it to the Web Animations API as the tooltip does, `element.animate(frames, animation)`. For SVG elements, `Svg#animate()` takes the CSS easing as it is. When the chart doesn't animate (a resize, `domRenderer()`, or a reader who prefers less motion), `animation` is absent, and your plugin doesn't animate either.

<Callout>
  **1.x plugins get a new SVG every time.** A chart with a plugin converted with
  `fromLegacyPlugin` draws a new SVG on every render, even with
  `liveDomRenderer()`, because 1.x `draw` listeners expect new elements. For a
  chart that updates live, write a v2 plugin like the one above.
</Callout>

## Sharing a plugin

A plugin is plain data and functions, so sharing one is publishing a module. Export a function that takes the options and returns the plugin, and type it with `ChartPlugin`:

```ts
import type { ChartPlugin } from 'chartist';

export interface HighlightOptions {
  className?: string;
}

export function highlightLast(options: HighlightOptions = {}): ChartPlugin {
  const className = options.className ?? 'ct-last';
  return {
    name: 'highlight-last',
    install(chart) {
      chart.on('compose', current => {
        if (current.role !== 'series') {
          return;
        }
        const last = current.children.at(-1);
        return last && current.replace(last, last.addClass(className));
      });
    }
  };
}
```

A few things keep a plugin working everywhere:

- Change the scene in `compose` and `scene`, not the DOM. Then it also works when the chart is [rendered to a string](../server-rendering/), where `render` and `mount` never happen.
- Touch elements only in `mount`, and only through `elementOf`.
- Set elements up on their `add` change, or return a cleanup function from `mount`. Then the plugin works with both renderers; see [Plugins for live updates](#plugins-for-live-updates).
- List `chartist` as a peer dependency, so your plugin uses the reader's copy.

## Publishing a plugin

Publish your plugin the way Chartist v2 is published: as an ES module with types.

```json
{
  "name": "chartist-plugin-highlight-last",
  "type": "module",
  "exports": {
    ".": { "types": "./dist/index.d.ts", "default": "./dist/index.js" }
  },
  "files": ["dist"],
  "keywords": ["chartist", "chartist-plugin"],
  "peerDependencies": { "chartist": "^2.0.0" },
  "sideEffects": false
}
```

- **Import, don't read globals.** Import what you need from `chartist`. Don't read the global `Chartist`: it only exists on pages that load Chartist's UMD build, or that import `chartist/compat` for old plugins.
- **No UMD build.** Pages without a bundler load ES modules directly from a CDN, and an import map tells the browser where `chartist` is, for your plugin's imports too:

  ```html
  <script type="importmap">
    {
      "imports": {
        "chartist": "https://cdn.jsdelivr.net/npm/chartist@2/dist/index.min.js"
      }
    }
  </script>
  <script type="module">
    import { lineChart } from 'chartist';
    import { highlightLast } from 'https://cdn.jsdelivr.net/npm/chartist-plugin-highlight-last/dist/index.js';

    lineChart('#chart', data, { plugins: [highlightLast()] });
  </script>
  ```

  Chartist still publishes a UMD build and a global `Chartist`, but only so that old pages and the plugins of 0.x keep working. They are for backwards compatibility, not something new plugins should build on.

- **Name it `chartist-plugin-…`** and add the `chartist-plugin` keyword, so people find it on npm.
- **Work in `compose` and `scene`** where you can. Then your plugin also draws when a chart is [rendered on a server](../server-rendering/), and the plugins page can tag it as SSR-capable.

**Don't forget to tell us about your plugin.** Once it's on npm, open a pull request that adds it to the [plugins page](../../plugins/), where readers find the community's plugins (the list is [`apps/docs/src/data/plugins.ts`](https://github.com/chartist-js/chartist/blob/next/apps/docs/src/data/plugins.ts)), or show it in [GitHub Discussions](https://github.com/chartist-js/chartist/discussions).

<Callout>
  **Coming from 1.x?** v2 charts don't emit `draw`, `created` or the other 1.x
  events. Listening to one logs a hint. Your 1.x plugins still run: wrap them
  with `fromLegacyPlugin` from `chartist/compat`. See [Coming from
  1.x](../coming-from-1x/), and the [plugins page](../../plugins/) for the
  community's plugins running on v2.
</Callout>
