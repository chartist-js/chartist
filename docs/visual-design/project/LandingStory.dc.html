How the easel knows where you are

A · recommended A tiny observer island. One IntersectionObserver with rootMargin: '-45% 0px' sets data-scene on the stage. Works in every current browser, about 30 lines, and does nothing if JavaScript is off: the hero chart simply stays.

B Pure CSS. Each chapter gets a view-timeline; timeline-scope on the story lets the stage layers fade by those timelines. Zero JS, but browser support for scroll-driven animations is still uneven, so it would need A as a fallback anyway.

C Chapter dots only. No scroll linking; readers tap the dots. Simplest, but loses the "he follows along" feeling.

reveal.css · draw-on-view.css
/* sections and cards rise in as they enter */
.reveal {
  animation: reveal-up linear both;
  animation-timeline: view();
  animation-range: entry 0% entry 70%;
}
/* charts draw as they scroll into view */
.ct-draw-view .ct-line {
  animation: ct-draw linear both;
  animation-timeline: view();
  animation-range: entry 20% cover 45%;
}
/* everything resolves to its final frame */
@media (prefers-reduced-motion: reduce) {
  .reveal, .ct-draw-view * { animation: none; }
}

One thing at a time

Only the stage animates while a chapter is in focus. Code blocks and text never move once revealed.

No scroll-jacking

Native scrolling, no snapping, no pinned full-screen scenes. The stage is plain position: sticky.

Keyboard & mobile

Chapter dots are buttons (44 px). On phones the stage pins at the top in a compact strip above the chapters.
